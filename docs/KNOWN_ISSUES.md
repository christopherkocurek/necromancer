# Known Issues

**Updated:** 2026-02-08 (post-Ralph Loop, Session S)

This document covers known bugs, unimplemented stubs, and visual issues in the current build. Items are grouped by severity and category.

---

## Minor Unimplemented Features

These are features that have stubs or TODOs in the code but lack gameplay implementation.

### Listen Ability (PER_LISTEN)

**File:** `scripts/core/constants.gd` line 143

The `PER_LISTEN` ability (index 7 in the Perception/Hunting skill tree) is defined in the constants enum but has no activation code. In Sil-Q, Listen reveals nearby monsters through walls when the player is stationary. The ability can be purchased with XP but currently has no effect.

**Impact:** Low. Players rarely invest in Listen early; other Hunting abilities are higher priority.

### Trap Reveal via Word of Opening

**File:** `scripts/systems/ability_system.gd` line 499

The Word of Opening ability (Lore ability 143) opens closed doors and clears rubble in a radius, but the trap reveal component is stubbed out with a `TODO: Reveal traps when trap system is implemented` comment. The ability otherwise functions correctly -- it costs 2 voice charges, has an 8-turn cooldown, and the radius scales with Lore skill.

**Impact:** Low. Traps exist in the game and can be disarmed with the D key, but Word of Opening does not reveal hidden ones.

### Silent Kill Detection

**File:** `scripts/core/constants.gd` line 128

The `STL_SILENT_KILL` stealth ability (index 11) is defined in the enum but has no gameplay hook. In Sil-Q, Silent Kill suppresses the noise generated by a killing blow, allowing stealth characters to chain kills without alerting nearby monsters. The ability can be purchased but currently does nothing.

**Impact:** Medium for stealth builds. Noise from kills still propagates normally.

### Sealed Door Mechanic

**File:** `scripts/systems/ability_system.gd` line 569

Word of Shutting (Lore ability 146) closes open doors but the comment at line 569 notes `TODO: Add sealed door flag to prevent monsters from opening`. Currently, doors closed by Word of Shutting are identical to normal closed doors -- monsters with the OPEN_DOOR flag can reopen them.

**Impact:** Low. The ability still provides tactical value by forcing monsters to spend a turn reopening the door.

### Equipment Resistance Checks

**File:** `scripts/systems/status_effects.gd` lines 224-226

The resistance check function has a `TODO: Check equipment for resistance flags` comment for Player entities. Equipment flags like RES_FIRE, RES_COLD, and RES_POIS are parsed from item data but not consulted during status effect application. Players wearing fire-resistant armor still take full fire damage from breath attacks.

**Impact:** Medium. Resistance equipment drops frequently in deeper layers but provides no defensive benefit beyond stat bonuses.

## Visual and Art Issues

### Layer Tile Quality Variation

The DALL-E terrain tiles (row 18 of the tileset) vary in visual quality across the 7 dungeon layers. Some layer-specific tiles (particularly the Throne Room set) have more visible AI artifacts than others. The Outer Pits and Lower Halls tiles are the most polished.

### Werewolf Placeholder Sprite

The werewolf monster uses the generic wolf sprite rather than a distinct werewolf design. A DALL-E-generated werewolf sprite was created but had color matching issues with the existing tileset palette.

### BONE_PILE Reuses RUBBLE Sprite

**Tile enum 24 (BONE_PILE)** shares the same sprite as RUBBLE because its dedicated row 18 slot was repurposed for the INSCRIPTION tile during Session R. This is a known cosmetic issue -- bone piles look identical to rubble piles.

### INSCRIPTION Placeholder Art

**Tile enum 27 (INSCRIPTION)** at tileset coordinates (10,18)/(11,18) uses a placeholder sprite that was rushed during the Session R tileset quality pass. The light/dark variants are functional but visually inconsistent with surrounding terrain tiles.

### Individual Sprite Issues

- Shadow Bat and Vampire Bat sprites are nearly identical at default zoom levels
- Some Necropolis-layer undead sprites have slight magenta fringing from the background removal pipeline
- The Fairy Flute item sprite is a recolored horn rather than a distinct flute design

## Engineering Issues

### RID Leak on Exit (4 CanvasItem)

When the game exits (via quit button or window close), Godot reports 4 leaked CanvasItem RIDs in the output console. These are leftover rendering resources from the UI layer that are not properly freed before shutdown. This does not affect gameplay and only appears in debug builds.

**Cause:** The UILayer CanvasLayer and its dynamically instantiated panels (voice_menu, item_menu, transition_overlay) are created with `new()` rather than scene instantiation, and some are not explicitly freed before the tree shuts down.

**Workaround:** None needed. The OS reclaims all memory on process exit. Fix would involve adding explicit `queue_free()` calls in a `_notification(NOTIFICATION_WM_CLOSE_REQUEST)` handler.

### BFS Connectivity Post-Decoration

After dungeon generation places decorative features (rubble, inscriptions, bone piles), there is no BFS validation pass to confirm that all rooms remain connected. In rare cases, aggressive rubble placement in narrow corridors can create isolated rooms that the player cannot reach.

**Frequency:** Estimated <1% of generated floors. The dungeon validation test suite (Stream C) catches most of these cases, but edge cases with vault placement can still occur.

**Impact:** Low. Auto-explore will report "no unexplored tiles reachable" if this happens. The player can descend or ascend to get a freshly generated floor.

### Monster Door-Opening AI

Monsters with the `OPEN_DOOR` flag (parsed from monster data) have the flag stored but the actual door-opening behavior is disconnected from the movement AI. Monsters cannot open closed doors, even when they have the flag set. They will path around doors instead.

### Level Regeneration on Return

Levels are not cached. Ascending and descending stairs regenerates the floor entirely -- all monsters, items, and terrain are re-rolled. This is a known simplification from the Sil-Q design where levels persist.

### Freed Instance Edge Cases

Despite widespread `is_instance_valid()` checks, there are occasional edge cases where a monster dies during turn processing (from a DOT effect) and subsequent systems attempt to reference the freed instance. These are mitigated but not fully eliminated.

## Balance Issues (Documented, Not Bugs)

These are design decisions that need tuning but are not bugs per se. See `docs/BALANCE_REPORT_SESSION_S.md` for full analysis.

- **Word of Command is overpowered** at Lore 8+: AOE fear + stun with 23 uses per rest from a 71-voice pool. Trivializes most floors.
- **Smithing damage dice not implemented**: Forged weapons gain attack/evasion bonuses but not damage dice, parry values, or weight modifiers. This makes smithing less impactful than intended.
- **Game difficulty below target**: Projected 40-75% win rate on Normal. Roguelike target is 1-5%. Needs empirical survival bot data before adjusting.
- **Song of the Trees (+5 stealth) and Song of Freedom (+3 evasion)** need mechanical grounding -- the bonus values are arbitrary and not derived from the Sil-Q formula.

## Not Yet Implemented (By Design)

These features are known gaps from the Sil-Q source that have not been prioritized:

- Pursuit Mode (6-phase escalation after taking the Ring)
- Ring gold hallucination effect
- Morgul-wound mechanic from Ringwraith attacks
- Lidless Eye Will checks at deep layers
- Level persistence (caching floors when ascending/descending)
- High score table persistence across runs
- 5 additional prisoner NPC types (only Thrain is implemented)
- HTML5 web export (needs export_presets.cfg)
